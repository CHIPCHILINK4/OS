#4
Длинные работы в workqueue ядра Linux


Требуется подготовить модуль ядра Linux (рекомендуется на основе модуля предыдущей работы), выполняющий длительные работы посредством механизма workqueue. Работа не должна выполняться в контексте системного вызова загрузки модуля, обработчика таймера или обработчика прерывания. После загрузки модуля должна создаваться собственная очередь работ.

После постановки работ в очередь функция загрузки модуля должна завершиться немедленно, не дожидаясь окончания работ. Во время выполнения работ модуль должен оставаться работоспособным и не должен обращаться к освобождённой памяти. При выгрузке модуля необходимо корректно дождаться завершения уже выполняющихся работ. Все работы, находящиеся в очереди, должны быть отменены или обработаны до уничтожения очереди. После выгрузки модуля в журнал ядра должна быть выведена информация о завершении или отмене всех работ. Модуль не должен оставлять после себя созданные очереди, таймеры, файлы или другие объекты ядра.

Очередь работ должна быть заполнена операциями, имитирующими сложный процесс. Имитированный сложный процесс должен состоять из серии последовательных этапов. Продолжительность каждого этапа должна составлять не менее одной секунды. Во время выполнения каждого этапа работа должна сообщать в журнал ядра свой идентификатор, номер этапа и общее количество этапов. Для имитации длительной операции следует использовать ожидание, допускающее засыпание потока, например msleep() или schedule_timeout_interruptible(). Запрещено имитировать длительную работу циклом, полностью занимающим процессор.

Параметры очереди и количество одновременно выполняемых работ должны определяться программой. На  уровне сложности «Hey, Not Too Rough», который достаточен для приёма лабораторной работы, при загрузке модуля необходимо поставить в очередь несколько работ со случайными параметрами.
Режим берсерка

При сдаче лабораторной работы в режиме берсерка можно выводить информацию о статусе работ в /proc/tsulab, а в режиме бешеного берсерка также запускать новые работы через запись команд в /proc/tsulab.
